# NLP、深度学习、LLM 与 Agent 的讲解重点

这些是遇到相应内容时的检查角度，不是每章都要追加的课程大纲。只补当前课件理解所需的部分；实验建议不是生成器已内置能力。

| 课件内容 | 优先讲清 | 值得展开的典型缺口 |
| --- | --- | --- |
| NLP 表示与任务 | 输入/输出、token 与词的关系、表示的含义、评价目标 | 用最小文本例子走通处理流程；避免只罗列术语 |
| 深度学习训练 | 前向计算、损失、参数更新、训练与推理的区别 | 梯度传播的关键步骤、张量形状、优化参数变化及失败条件 |
| Attention / Transformer | 每步输入输出与信息如何混合 | 小矩阵 Q/K/V、缩放/mask/归一化、加权结果；说明简化与维度约定 |
| LLM 目标与生成 | 哪些位置预测什么、上下文与生成顺序 | 一个目标或解码步骤的可复算例子；区分训练目标与生成策略 |
| 检索与 RAG | 查询、检索证据、上下文组织和回答之间的关系 | 失败发生在哪个环节；检索到相关材料并不自动说明回答正确 |
| Agent / tools / memory | 模型输出、工具执行、观察结果和状态变化 | 实际调用/返回如何对应、暂停恢复、停止条件、预算；区分教学伪代码与真实协议 |
| 模型或系统对比 | 解决的任务、数据/计算条件、证据来源 | 对比建立在一致条件上；不要从示意图编造效果、性能或优劣结论 |

## 例子和交互的选择

- 定义、背景、组件清单通常用简述与原页对照。
- 一个计算步骤优先用手算例子；矩阵或状态变化确实难观察时再做可视化。
- 改学习率、mask、概率分布或调用顺序只有在对应章节出现并影响所学机制时才值得交互。
- Agent 可用小状态机、消息记录或有限步骤模拟，不因课程谈工具就实际调用搜索、付费 API、订票等外部服务。
- 离线计算实验注明固定输入、简化维度、规则或数据来源；不要暗示运行了预训练 LLM。
- 优先复用当前任务或用户提供的已验证实验；没有可用资源时才新增最小实现。当前内置仍只有 convolution / output_shape，不能声称 Attention、解码或 Agent 实验已经内置。

## 练习方向

先检查直觉/反例，再按需要计算或判断流程，最后选择一个跨页应用。关注“为什么”“哪一步错了”“这个条件改变后结果如何变化”，不把术语背诵题铺满每页。

开放解释题可以提供答案要点供自评；当前判分器不支持自由文本理解，不要声称语义判分。概念错误选项须有唯一正确答案，复杂实际场景应写清假设。
